# verify: 증거로 확인하기

원칙: 명령과 출력이라는 증거 없이 "완료"라고 하지 않는다.

1. **자동 점검**: `bash .agents/skills/verify/scripts/check.sh`
   - 프로젝트를 감지해 파이썬 문법, pytest, ruff 치명적 오류, npm test·lint·typecheck, tsc, Go 테스트, 비밀키 노출을 점검하고 결과를 `notes/VERIFY.md`에 남긴다.
   - 빌드까지 확인하려면 `--build`를 붙인다.
   - pytest나 ruff가 미설치로 나오면 필요한 것만 `pip install`로 설치하고 다시 돌린다.
2. **실패하면**: 원인을 한 줄로 진단하고 최소한으로 고친 뒤 1번을 다시 돌린다. 같은 실패가 두 번 나오면 멈추고 가설과 선택지를 사용자에게 보고한다.
3. **테스트 보강**: 이번 변경의 핵심 로직에 테스트가 없으면 추가한다(정상 1개 + 경계·예외 1~2개). 기대값은 요구사항에서 가져오고, 통과시키려고 바꾸지 않는다.
4. **실제 실행**: 주요 경로를 실제 명령으로 한 번 돌린다.
   - 서버: 백그라운드로 띄우고 `curl`로 핵심 엔드포인트 1~2개를 호출한 뒤 프로세스를 종료한다.
   - CLI·스크립트: 샘플 입력으로 실행하고 출력 일부를 확인한다.
   - 데이터·ML: 지표를 실제로 계산하고 단순 기준선과 비교한다.
5. **성공 기준 대조**: `notes/PROBLEM.md`의 기준마다 충족/부분/미충족과 증거(명령, 수치, 파일:줄)를 `notes/VERIFY.md`에 추가하고, PROBLEM.md의 상태 열도 갱신한다.
6. **기록과 커밋**: `notes/PLAN.md`의 상태를 갱신한다. `git status --short`로 확인하고 의도한 파일만 add 한 뒤 커밋한다.
   `git commit -m "<type>: <무엇을, 왜> (verified: <핵심 증거>)"` (push 금지)
