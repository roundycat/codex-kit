# cross-check: 독립 리뷰

목적: 만든 쪽과 다른 시선으로 결과를 검증한다.
- 가능하면 새 세션에서 실행한다. 다른 터미널에서 `codex`를 새로 띄우는 게 가장 좋고, 안 되면 `$handoff`를 먼저 한 뒤 `/new`로 연다. 같은 세션에서 돌린다면 기억에 기대지 말고 파일을 다시 읽는다.
- 리뷰 중에는 코드를 수정하지 않는다. 재현용 임시 스크립트는 `/tmp`에만 만든다.

## 순서
1. **읽기**: `AGENTS.md`, `notes/PROBLEM.md`(성공 기준), `notes/PLAN.md`, `git log --oneline -20`, 마지막 리뷰 이후의 변경(`git diff <기준 커밋>..HEAD --stat`으로 범위를 본 뒤 핵심 파일).
2. **점검** (중요한 순서대로):
   - 요구사항: 성공 기준마다 실제 구현과 증거가 있는가? 문서에 쓴 내용과 코드·커밋이 일치하는가?
   - 정확성: 빈 입력, 잘못된 입력, 경계값, 단위와 타입, 오프바이원, 예외 처리.
   - 데이터·ML(해당 시): 데이터 누수, 학습/검증 분리, 시드 고정, 기준선 대비 성능, 지표 선택의 타당성.
   - 보안·운영: 하드코딩된 키, 입력 검증, 민감정보 로그, 외부 호출 실패 시 동작.
   - 과잉 구현: 성공 기준과 무관한 기능, 불필요한 복잡도.
3. **직접 확인**: 의심 지점은 실행해서 확인한다(테스트 실행, `/tmp`의 작은 재현 스크립트).
4. **기록**: `notes/REVIEW.md`에 심각도순으로 적는다. 파일이 없으면 만든다.
   `[H|M|L] 파일:줄 — 문제 / 근거(재현 명령이나 코드) / 제안`
5. **보고**: H 항목을 먼저 한 줄씩 쓰고, 마지막에 "지금 고칠 것 / 미룰 것"을 추천한다.

## 리뷰 후 처리
H·M 항목을 고치고, 각 항목 옆에 처리 결과(수정 커밋 해시 또는 미룬 이유)를 적은 뒤 `$verify`로 확인한다.
