# kickoff: 문제 정의와 계획

목표: 코드를 쓰기 전에 무엇을 만들어야 하는지(R)와 무엇이 성공인지(S)를 확인 가능한 형태로 정하고, 작업을 검증 가능한 단계로 나눈다. 이 스킬을 진행하는 동안에는 코드를 고치지 않는다.

## 1. 시간 (1분)
1. 사용자 메시지에 타이머의 남은 시간이나 종료 시각이 있으면 그것을 쓴다. 없으면 묻고, 기다리는 동안 2단계를 진행한다. 답이 없으면 지금부터 175분 뒤를 종료 시각으로 두고 가정으로 기록한다.
2. 현재 시각은 `TZ=KST-9 date +%H:%M`, 종료 시각은 `TZ=KST-9 date -d '+<남은 분> min' +%H:%M`로 구한다. `notes/PLAN.md`에 종료 시각과 마무리 시작 시각(종료 20분 전)을 적는다.

## 2. 정찰 (읽기만, 5분 안에)
1. `git log --oneline -5`, 최상위 파일 목록, README와 과제 설명, 데이터, 기존 코드와 테스트를 본다. 과제 설명이 저장소에 없으면(플랫폼 화면에만 있으면) 사용자에게 붙여 달라고 한다.
2. 데이터는 크기, 컬럼, 앞부분 몇 줄, 결측·이상치만 요약한다. 전체를 출력하지 않는다.
3. 실행 환경을 확인한다: 언어와 버전, 설치된 패키지, 실행·테스트 명령.

## 3. 요구사항과 질문
사용자에게 짧게 보고한다.
- 과제 한 줄 요약: 누가, 무엇 때문에, 무엇을 원하나
- 요구사항(R) 목록: 과제 설명에 명시된 기능 요구와 제출 조건(제출물, 위치, 형식, 실행 방법, 평가 방식)을 빠짐없이, 출처와 함께
- 비어 있거나 모호한 부분
- 실무자에게 물을 질문 5~7개(우선순위순). 해법 단어(AI, 자동화, 대시보드 등)를 피하고 문제 자체를 묻는다. 사용자가 그대로 보내거나 자기 말로 바꿔 보낼 수 있게 한 문장씩 쓴다.
  1. 최근에 이 문제가 실제로 생긴 구체적 사례
  2. 지금의 우회 방법과 그 비용(시간, 돈, 실수)
  3. 빈도, 규모, 현재 수치
  4. 누가 쓰고 누가 결과를 받는지
  5. 이번에 안 해도 되는 것, 절대 틀리면 안 되는 것
  6. 무엇을 보면 "됐다"고 판단할지
- 과제 설명에 이미 답이 있는 질문은 빼거나 확인용으로 바꾼다.

여기서 멈추고, 사용자가 실무자의 답(또는 "가정으로 진행")을 전해 주기를 기다린다.

## 4. 문제 정의서
`notes/PROBLEM.md`를 채운다.
- R은 과제 설명의 요구를 빠짐없이 옮기고, 각 R에 출처(파일:줄 또는 "과제 화면")를 단다.
- S는 3~5개. 각 기준은 측정 가능하고 검증 방법(명령, 테스트, 수치)을 가지며, 관련 R을 적는다. 실무자의 답에서 나온 기준을 우선한다.
- 만들 것과 만들지 않을 것을 나눈다.
- 확인되지 않은 내용은 근거와 함께 "가정"에 적는다.
- 인터뷰 기록에는 사용자가 전한 질문과 답의 핵심만, 받은 시각과 함께 적는다.

그다음 사용자가 실무자에게 보낼 3~5줄짜리 확인 메시지 초안(이해한 문제, 성공 기준, 만들지 않을 것)을 준다.

## 5. 계획
`notes/PLAN.md`에 단계를 쓴다.
- 1단계는 끝에서 끝까지 동작하는 최소 버전(E2E v0)이다.
- 각 단계는 30분 이하이고, 관련 R·S, 완료 조건, 검증 방법을 갖는다.
- 위험이 큰 부분(데이터 품질, 외부 의존, 성능)은 앞 단계에서 확인한다.
- 담당 열에 Codex가 실행할 일과 사용자가 판단할 일을 구분한다.
- 마무리 시작 시각 이후는 `$wrap-up` 몫으로 비워 둔다.
- 앞 단계에 필요한 되돌리기 어려운 선택(전체 구조, 데이터 모델, 알고리즘·모델, 무거운 의존성)은 선택지와 추천안, 이유로 정리해 계획 보고에 함께 낸다. 사용자가 고르면 결정자 "사용자"로 `notes/DECISIONS.md`에 적는다.

## 6. 저장소 정보와 커밋
1. `AGENTS.md`의 "이 저장소" 절에 과제, 실행·테스트 명령, 주요 경로, 데이터, 주의할 점을 채운다. 아직 모르는 칸은 비워 둔다.
2. `git add notes AGENTS.md && git commit -m "docs: 요구사항 R<n>개·성공 기준 S<n>개와 계획 작성" -- notes AGENTS.md` (push 금지)

보고: R·S 목록, 첫 3단계, 사용자가 정할 것(S 확정, 범위, 핵심 결정의 선택지). 사용자가 S와 계획을 확인하고 핵심 결정을 고르면 1단계를 시작한다.
