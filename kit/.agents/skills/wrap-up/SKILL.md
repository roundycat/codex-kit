# wrap-up: 제출 마무리

지금부터 새 기능은 만들지 않는다. 작동하는 것을 지키는 게 우선이다.

1. **동결**: 미완성 변경은 되돌리거나(`git stash` 또는 해당 파일 복원) 동작하는 최소 상태로 정리한다. 깨진 코드를 남기지 않는다.
2. **최종 검증**: `bash .agents/skills/verify/scripts/check.sh`와 핵심 실행 경로 1회. 실패하면 가장 작은 수정만 하거나 그 기능을 끄고 README에 적는다.
3. **README**: 과제 원문이 있으면 지우지 말고 아래에 섹션을 추가한다.
   - 무엇을 만들었나 (2~3줄)
   - 실행 방법과 테스트 방법 (복사해서 바로 쓰는 명령)
   - 성공 기준별 결과 (수치와 증거)
   - 한계와 다음 단계 (정직하게)
4. **문서 최신화**: `notes/PLAN.md` 상태, `notes/DECISIONS.md`의 결정과 리스크, `notes/HANDOFF.md`를 최종 상태로 맞춘다.
5. **청소**: 디버그 출력, 임시 파일, 주석 처리된 죽은 코드를 지우고, 비밀키가 코드에 없는지 확인한다.
6. **최종 커밋**: `git status`가 깨끗해질 때까지 정리하고 `git commit -m "chore: final cleanup and docs"`. push 금지. 플랫폼의 제출 버튼은 사용자가 직접 누른다.
7. **브리핑** (사용자가 3분 안에 읽을 수 있게):
   - 무엇을, 왜 만들었나
   - 핵심 구조와 동작 원리
   - 성공 기준별 결과
   - 가장 큰 리스크 2~3개: 어디가(파일:줄) → 왜 위험한가 → 다음에 무엇을 검증·개선할지
