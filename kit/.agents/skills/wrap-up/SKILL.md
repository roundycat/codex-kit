# wrap-up: 제출 마무리

지금부터 새 기능은 만들지 않는다. 작동하는 것을 지키는 게 우선이다.

1. **동결**: `git status --short`로 미완성 변경을 확인한다. 몇 분 안에 끝내고 검증할 수 있는 것만 마무리한다. 남길 수 없는 미완성 변경은 목록과 함께 되돌릴지 바로 사용자에게 묻고, 사용자가 확인한 뒤에만 되돌린다.
2. **요구사항 대조**: `notes/PROBLEM.md`의 R을 하나씩 확인한다. 특히 제출 조건(제출 파일과 위치, 형식, 실행 명령)은 실제로 확인하고, 빠진 것은 가장 작은 조치로 채우거나 README에 적는다.
3. **정리**: 직접 추가한 디버그 출력과 주석 처리된 죽은 코드를 지운다. 과제가 준 파일과 결과물은 지우지 않는다.
4. **최종 검증**: `bash .agents/skills/verify/scripts/check.sh`와 핵심 실행 경로 1회. 실패하면 가장 작은 수정만 하거나, 그 기능을 끄고 README에 적는다. 이 뒤로는 코드를 고치지 않는다.
5. **README**: 과제 원문이 있으면 지우지 말고 아래에 섹션을 추가한다.
   - 무엇을 만들었나 (2~3줄)
   - 실행 방법과 테스트 방법 (복사해서 바로 쓰는 명령)
   - R·S별 결과 (수치와 증거)
   - 한계와 다음 단계 (정직하게)
6. **기록 최신화**: `notes/PLAN.md` 상태, `notes/DECISIONS.md`의 결정과 리스크, `notes/HANDOFF.md`, `AGENTS.md`의 "이 저장소" 절을 최종 상태로 맞춘다.
7. **최종 커밋**: 제출할 파일만 지정해 `git add <파일...> && git commit -m "chore: 제출 전 정리와 문서 최신화" -- <파일...>`. 그 뒤 `git status --short`로 남은 변경과 커밋하지 않은 파일을 보고한다. push 금지. 플랫폼의 제출 버튼은 사용자가 누른다.
8. **브리핑** (3분 안에 읽을 수 있게):
   - 무엇을, 왜 만들었나
   - 핵심 구조와 동작 원리
   - R·S별 결과
   - 가장 큰 리스크 2~3개: 어디가(파일:줄) → 왜 위험한가 → 다음에 무엇을 검증·개선할지
